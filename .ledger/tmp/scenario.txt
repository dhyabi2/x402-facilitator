END-TO-END PROBE: a Nano (XNO) resource server adopts the new exact scheme. Each law is proven through a DISTINCT component, and the proving assertion is quoted from the test file verbatim so the judge can verify it.

### L0 — verify reads amount/destination/subtype from the on-chain block, never the request body
Component: the block-fetch + verify path (verifier reads the block the node returns).
Proving test (scheme/nano/facilitator/nano_test.go, verbatim assertion):
    res, err := f.Verify(t.Context(), nanoPayload(testBlockHash, req), req)
    require.NoError(t, err)
    require.True(t, res.IsValid)
    require.Equal(t, node.info.Account, res.Payer)
    require.Equal(t, testBlockHash, node.hash)
The payer and the proof binding come from the block the node returns (block_account), so a wrong-body claim cannot pass: TestNanoVerifyRejectsInvalidBlocks/wrong_destination requires recipient_mismatch and wrong_amount requires amount_mismatch, both driven by reading the block's own destination/amount.

### L1 — Settle is stateless re-verification; no broadcast, no custody key
Component: the settle path (a single read; nothing broadcast or signed).
Proving test (scheme/nano/facilitator/nano_test.go, verbatim assertions):
    res, err := f.Settle(t.Context(), nanoPayload(testBlockHash, req), req)
    require.NoError(t, err)
    require.True(t, res.Success)
    require.Equal(t, testBlockHash, res.Transaction)
    require.Equal(t, node.info.Account, res.Payer)
    require.Equal(t, 1, node.calls, "settle must be a single read, nothing more")
And nano.go verbatim constructor signature carries no private key:
    func NewNanoFacilitator(network, apiKey string, rpcURLs ...string) (*NanoFacilitator, error)
apiKey is an RPC header value, not a signing key; there is no broadcast and no custody key.

### L2 — the registry routes nano: to the no-key nano facilitator
Component: distribution-level dispatch (cmd/facilitator registry).
Proving test (cmd/facilitator/registry_test.go, verbatim row):
    {name: "nano prefix routes to nano constructor", scheme: types.Exact, network: "nano:", errContains: []string{"invalid Nano network"}}
The nano: prefix reaching NewNanoFacilitator (invalid-network error) rather than the generic "expected a CAIP-2 identifier" default proves routing.

Each law names a different component (verify-fetch, settle, registry dispatch), so the distinct-components rule is met. The oracle is `go test ./scheme/nano/facilitator/ && echo PASS` which returns PASS only when all tests (including these asserts) pass.
